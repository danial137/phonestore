# پرشین موبایل | Persian Mobile

فروشگاه فارسی و راست‌به‌چپ با Next.js App Router، React، TypeScript و دیتابیس SQLite. رابط دسکتاپ و موبایل، فونت Vazirmatn محلی و آیکون‌های Lucide دارد؛ برای اجرا به سرویس دیتابیس خارجی نیاز نیست.

> این تحویل یک برنامه قابل اجرا با داده‌های نمایشی است. قیمت، موجودی، مشخصات و تصاویر اولیه برای نمایش هستند. فروش عمومی، ارسال واقعی و درگاه زنده در این محیط فعال نشده‌اند.

## اجرای سریع

پیش‌نیاز: **Node.js 24 یا بالاتر** و npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

در ویندوز به‌جای دستور `cp` از `copy .env.example .env.local` استفاده کنید. سپس [http://localhost:3000](http://localhost:3000) را باز کنید. دیتابیس و ۱۲ محصول نمونه در اولین درخواست ایجاد می‌شوند.

اجرای نسخه production:

```bash
npm run build
npm start
```

ساخت حساب مدیر، پس از یک بار باز کردن سایت:

```bash
npm run admin:create
```

ایمیل، نام و رمز دلخواه را وارد کنید. حداقل رمز مدیر ۱۲ کاراکتر است. رمز در حالت تعاملی این اسکریپت روی ترمینال نمایش داده می‌شود؛ برای محیط عملیاتی می‌توانید `ADMIN_EMAIL`، `ADMIN_NAME` و `ADMIN_PASSWORD` را از secret manager در محیط فرایند قرار دهید. اسکریپت رمز را چاپ یا ذخیره متنی نمی‌کند و حساب موجود را تغییر نمی‌دهد. **هیچ حساب یا رمز مدیر پیش‌فرضی وجود ندارد.**

از `/auth` وارد شوید و `/admin` را باز کنید. کاربران عادی از صفحه ثبت‌نام حساب می‌سازند.

## قابلیت‌های پیاده‌سازی‌شده

- صفحه اصلی فارسی، واکنش‌گرا، با دسته‌بندی و پیشنهاد محصولات.
- کاتالوگ با جستجو، برند، دسته، محدوده قیمت، موجودی، تخفیف و مرتب‌سازی.
- جزئیات محصول، انتخاب رنگ، مشخصات و تعداد؛ عکس HTTPS قابل تنظیم در مدیریت و تصویر شماتیک جایگزین.
- مقایسه حداکثر سه کالا و علاقه‌مندی‌ها.
- سبد خرید پایدار در همان مرورگر؛ تغییر تعداد و حذف کالا.
- ثبت‌نام، ورود، خروج، ویرایش نام و تغییر رمز عبور.
- اعتبارسنجی اطلاعات تحویل؛ پشتیبانی از ارقام فارسی در تلفن و کد پستی.
- محاسبه قیمت، تخفیف، هزینه ارسال و اعتبارسنجی موجودی در سرور.
- ثبت سفارش تراکنشی، کلید جلوگیری از سفارش تکراری و کنترل خرید هم‌زمان.
- ثبت سفارش پرداخت هنگام تحویل و اتصال قابل تنظیم زرین‌پال.
- سوابق و جزئیات سفارش، وضعیت پردازش و لغو سفارش مجاز.
- مدیریت ایجاد/ویرایش/مخفی‌کردن محصول، قیمت، موجودی، مشخصات، رنگ، تصویر و محصول منتخب.
- مدیریت وضعیت سفارش، مشاهده اطلاعات تحویل و خروجی CSV.
- ساخت و فعال/غیرفعال کردن کد تخفیف با سقف مبلغ و سقف استفاده.
- تیکت داخلی مشتری و پاسخ مدیر، همراه با سؤال‌های پرتکرار و صفحات راهنما.
- هش رمز با scrypt، توکن نشست تصادفی و ذخیره هش آن، کوکی HttpOnly، کنترل Origin، محدودسازی درخواست و اعتبارسنجی Zod.
- Docker، دیتابیس پایدار و اسکریپت پشتیبان‌گیری.

سبد، مقایسه و علاقه‌مندی‌ها روی همان دستگاه نگهداری می‌شوند؛ حساب، محصولات، سفارش‌ها، تخفیف‌ها و پیام‌ها در دیتابیس هستند. هیچ ایمیل، پیامک، فاکتور مالیاتی یا اعلان بیرونی ارسال نمی‌شود.

## تنظیمات

| متغیر | کاربرد |
|---|---|
| `APP_URL` | آدرس دقیق فروشگاه، برای کنترل مبدأ درخواست و بازگشت از پرداخت |
| `DATABASE_PATH` | مسیر فایل SQLite؛ پیش‌فرض `./data/store.sqlite` |
| `COOKIE_SECURE` | روی دامنه HTTPS واقعی باید `true` شود؛ برای localhost HTTP مقدار `false` |
| `ZARINPAL_MERCHANT_ID` | شناسه پذیرنده؛ خالی باشد پرداخت آنلاین نمایش داده نمی‌شود |
| `ZARINPAL_SANDBOX` | `true` برای آزمایش، `false` برای درگاه واقعی |

همیشه `APP_URL` را با آدرسی که در مرورگر باز می‌کنید یکسان قرار دهید؛ `localhost` و `127.0.0.1` مبدأ یکسانی نیستند.

تنظیمات فعلی تجارت در `src/lib/commerce.ts`:

- ارسال سفارش با مبلغ کالا از ۲۰٬۰۰۰٬۰۰۰ تومان: رایگان؛ کمتر از آن: ۹۰٬۰۰۰ تومان.
- حداکثر ۱۰ عدد از هر محصول در یک سفارش، با کنترل جمع تمام رنگ‌ها.
- کد نمایشی `WELCOME`: پنج درصد، با سقف ۵۰۰٬۰۰۰ تومان و ظرفیت ۱۰۰ استفاده.
- موجودی در زمان ثبت سفارش رزرو می‌شود؛ لغو سفارش پرداخت هنگام تحویل قبل از آماده‌سازی، موجودی و ظرفیت تخفیف را بازمی‌گرداند.

## پرداخت آنلاین

در صورت تنظیم شناسه پذیرنده، گزینه زرین‌پال در checkout نمایش داده می‌شود. مبلغ فروشگاه به تومان است و درخواست درگاه آن را به ریال تبدیل می‌کند. تأیید پرداخت با استعلام مستقیم سرور انجام می‌شود؛ پارامتر بازگشت مرورگر به‌تنهایی پرداخت را تأیید نمی‌کند. کدهای موفق ۱۰۰ و ۱۰۱ پشتیبانی می‌شوند.

1. برای تست، `ZARINPAL_SANDBOX=true` و شناسه تست معتبر قرار دهید.
2. `APP_URL` باید یک آدرس در دسترس برای بازگشت مرورگر باشد.
3. قبل از استفاده زنده، درخواست، بازگشت، پرداخت ناموفق و تکرار callback را با حساب پذیرنده خود آزمایش کنید.

در این تحویل، ارتباط زنده با حساب پذیرنده و انتقال پول آزمایش نشده است. مستندات مرجع: [اتصال زرین‌پال](https://www.zarinpal.com/docs/paymentGateway/connectToGateway) و [سندباکس](https://www.zarinpal.com/docs/paymentGateway/sandBox).

**رزرو سفارش پرداخت‌نشده:** در صورت نامشخص بودن پاسخ درگاه، موجودی برای جلوگیری از فروش دوباره آزاد نمی‌شود. تراکنش دارای authority را باید با درگاه تطبیق دهید. انقضای خودکار رزرو، تطبیق دوره‌ای درگاه و بازپرداخت خودکار پیاده نشده‌اند. سفارش pending بدون authority از API لغو قابل آزادسازی است. سفارش‌های پرداخت‌شده عمداً دکمه لغو خودکار ندارند؛ بازپرداخت باید از مسیر عملیاتی پذیرنده انجام شود.

## تست

```bash
npm run typecheck
npm run build
npm test
```

تست‌ها سرور production را روی پورت ۳۱۰۰ و دیتابیس **موقت و جداگانه** اجرا می‌کنند و به اطلاعات اصلی فروشگاه دست نمی‌زنند. پورت ۳۱۰۰ باید آزاد باشد. تست مرورگر در Linux از Chromium بسته‌بندی‌شده استفاده می‌کند؛ در macOS یا Windows یک بار `npx playwright install chromium` اجرا کنید.

پوشش تست: احراز هویت، CSRF، دسترسی مدیر، قیمت سمت سرور، تخفیف، موجودی مشترک رنگ‌ها، idempotency، مالکیت سفارش، برگشت موجودی، رقابت روی آخرین کالا، تغییر وضعیت، CRUD، تیکت، و مسیر خرید کامل در مرورگر موبایل. تصاویر دسکتاپ، موبایل و مدیریت در `test-results/` ذخیره می‌شوند.

تست‌های درگاه زنده، مرورگر Safari/Firefox و Docker روی میزبان نهایی باید در محیط مقصد انجام شوند.

## استقرار با Docker

ابتدا `.env.local` را بسازید و تنظیمات دامنه و کوکی را کامل کنید:

```bash
docker compose up --build -d
```

پس از باز کردن سایت برای مقداردهی دیتابیس:

```bash
docker compose exec store npm run admin:create
```

این معماری برای **یک فرایند Node روی یک میزبان با دیسک پایدار** مناسب است. SQLite را روی فایل‌سیستم موقت سرورلس یا میان چند replica قرار ندهید. برای مقیاس افقی باید لایه داده به PostgreSQL و محدودسازی درخواست به یک مخزن مشترک منتقل شود. دامنه را با reverse proxy و TLS به پورت برنامه وصل کنید.

## پشتیبان‌گیری

```bash
npm run db:backup
# یا:
npm run db:backup -- ./backups/my-backup.sqlite
```

اسکریپت از SQLite backup API استفاده می‌کند، بنابراین WAL را به روش صحیح در یک snapshot مستقل لحاظ می‌کند. در Docker از `docker compose exec store npm run db:backup` استفاده کنید و فایل پشتیبان را خارج از سرور نیز نگه دارید. برای بازیابی، سرویس را متوقف کنید، از فایل فعلی و فایل‌های جانبی آن پشتیبان بگیرید، snapshot انتخابی را جایگزین کنید و سپس سرویس را دوباره اجرا کنید.

## ساختار پروژه

```text
src/app/                 صفحات App Router و مسیرهای API
src/components/          اجزای فروشگاه، حساب، مدیریت و رابط خرید
src/lib/db.ts            schema، seed و دسترسی SQLite
src/lib/commerce.ts      قیمت‌گذاری، موجودی، سفارش و لغو
src/lib/security.ts      نشست، رمز عبور، CSRF و rate limit
src/lib/payments.ts      درخواست و تأیید زرین‌پال
src/lib/seed.ts          محصولات نمونه
scripts/                ایجاد مدیر و پشتیبان‌گیری
tests/                  تست API و مرورگر
```

مسیرهای API اصلی زیر `/api/` هستند: `products`، `me`، `auth/register`، `auth/login`، `auth/logout`، `auth/password`، `checkout/quote`، `orders`، `orders/:id`، `orders/:id/cancel`، `orders/:id/pay`، `tickets`، `admin`، `admin/products`، `admin/orders/:id`، `admin/coupons`، `admin/tickets/:id` و `payments/callback`. درخواست‌های تغییردهنده JSON و Origin همان سایت نیاز دارند؛ عملیات مدیر علاوه بر آن نشست مدیر لازم دارد.

## پیش از فروش واقعی

محصولات و عکس‌های واقعی، قیمت و موجودی تأییدشده، هویت و اطلاعات تماس فروشنده، ضمانت و رجیستری، قواعد ارسال و مرجوعی را تنظیم کنید. وضعیت نمایشی در footer، about، checkout و policies مشخص شده؛ پس از آماده‌سازی کسب‌وکار متن‌ها را اصلاح کنید. `robots` فعلاً `noindex` است تا داده نمایشی ایندکس نشود.

ارسال ایمیل تأیید، بازیابی رمز با ایمیل، ورود پیامکی، MFA، آپلود فایل تصویر، انبارهای متعدد، اتصال حمل‌ونقل، مالیات، امتیاز و نقد کاربران و گزارش‌های صفحه‌بندی‌شده در این دامنه پیاده نشده‌اند. مدیر فعلاً ۲۰۰ سفارش و پیام اخیر را می‌بیند. عکس محصولات از URL HTTPS تنظیم می‌شود. بدون سرویس پیام‌رسانی، بازیابی خودکار رمز در دسترس نیست؛ دسترسی اجرایی مدیر و راه پشتیبانی باید در محیط واقعی مشخص باشد.
